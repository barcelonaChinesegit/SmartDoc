# SmartDoc 数据调研讨论提纲

日期：2026 年 11 月 19 日

详细方法、来源和局限见[数据调研与构建方案](data_research_zh.md)，文献 PDF 见[本地索引](../papers/INDEX.md)。下面的数据量都是试运行建议，具体取决于工具、人力和数据许可。

## 先对齐我们要准备什么

我理解现阶段先搭一个不训练的文档智能体原型，所以数据侧要先能判断它回答对不对、证据找得准不准，以及中间工具有没有用对。后续如果要做 SFT 或 Agentic RL，再准备工具调用示范和可重放交互任务。

我这次重点选了几篇与这几件事直接相关的工作，想先讨论它们怎么落到我们的数据上。

## 评测：答案和证据分开看

**LongDocURL** 做了一个长文档基准：2,325 道问答覆盖 396 份文档，分理解、数值推理、跨元素定位三类，证据可能来自正文、表格或图，约一半问题跨页。它先解析 PDF、生成候选问答，再自动检查并由人对照原页面复核。

对我们最有用的是按任务类型、证据类型和是否跨页组织评测。比如同样问报告里的增长率，可以区分答案在正文、在表格，还是需要跨页比较；不只给一道题一个正确答案，还记录支持它的是哪份文档、哪几页。这里要注意，它的“定位”还包括从段落找标题，不能直接等同于我们需要的坐标定位；而且不可回答题很少，我们要另外补。

**QASPER** 是 1,585 篇 NLP 论文上的 5,049 个问题。提问者先看摘要提问，另一组人阅读全文回答和标证据，答案可以是抽取、归纳、是/否或不可回答。它分别算答案和证据的 F1，并按论文切分数据。

我们可以先拿 QASPER 的测试划分跑通问答与证据评价，训练和测试也按文档分开。它适合论文阅读场景，但不是合同或表格的完整替代，证据也不能假定都有 PDF 页码；格式适配和许可仍需核对。

## 轨迹：一次真实工具执行应该怎么记录

**DocAgent** 先把文档整理成有章节、页码和元素 ID 的树状目录，再让执行智能体根据问题读取相关内容；它还用了审查智能体交叉核对答案和记忆。我们可以借鉴目录和按需读取：把“看目录、搜索、读页、回答或复核”各步的工具名、参数、实际返回和证据 ID 记下来。

这篇给的是系统设计，不是我们可以直接拿来训练的文档轨迹。多智能体、额外复核会增加调用成本，后面应和单智能体方案比较，不能先假定更好。

**ToolACE** 解决的是如何合成多样的函数调用数据。它生成工具和对话，覆盖单次、并行、依赖调用以及无需调用，之后用规则和模型两层检查。对我们的启发是先固定实际工具 schema，再围绕单页检索、跨页依赖、多文档比较、澄清和失败重试生成示范。

有一个区别要说清楚：ToolACE 的工具角色可以模拟结果。我们自己的文档示范应尽量实际运行解析和检索工具，用真实返回填观察，再核验答案和页码，不能让教师模型直接编一个工具结果。

举个要做的样例：用户问两份合同的续约周期差异，模型分别查 A、B 的条款，读取实际页码和内容，再比较并引用。如果 B 没搜到，示范应该继续查或说明证据不足，而不是猜。

## RL 和过程评测：借鉴什么，不预设什么

**Search-R1** 把检索器作为环境：模型发查询，工具返回文本，模型继续搜索或回答。训练时它遮蔽检索返回的 token，采用最终答案奖励。这正好对应我们之前讨论的疑问：工具返回要给模型作为后续上下文，但不应当成模型自己生成的目标来训练；具体掩码需要训练框架实现并验证。

我们的改造是把搜索环境换成文档解析、检索和读取工具。先验证任务能不能重置、工具返回能不能复现，先用答案和证据做终局奖励，再通过实验决定是否加过程奖励。Search-R1 本身并没有证明过程奖励一定必要。

**TRAJECT-Bench** 在最终答案外，还看工具选得对不对、参数是否满足约束、必需调用及依赖顺序是否正确。它还用直接和隐含两种问法测试同一轨迹。我们可以借鉴这些检查项，做文档任务的过程评测；但不同工具路径可能都合理，所以不能只按一条标准轨迹是否完全一致打分。

**ProcessBench** 是数学过程评测，由专家标出解题过程中最早出错的步骤，模型需要找出错误或判断全程正确。我们的文档场景可以借鉴标注方式：从实际轨迹里找第一次明确错误，比如查错文档、读错工具返回、没有证据却作答。工具故障和多条合理路径会让标注更难，因此先做少量双人试标，看一致性，再决定要不要做过程奖励模型。

## 接下来怎么试

1. 先和负责系统的同学对齐首批工具、输入输出、文档版本，以及日志能否保存真实返回。
2. 核对 QASPER 和 LongDocURL 的数据下载、切分和许可，各抽 20–50 题试跑；自建少量合成文档题，补充不可回答、失败恢复与引用检查。
3. 系统工具可用后，先制作 50–100 条文档 SFT 候选示范，真实执行并检查工具调用、返回、证据和答案。
4. 环境能重置后，试 20–50 个可重放任务；从真实轨迹中抽 30–50 条双人标注首错，评估一致性，再决定是否扩量。

## 最后总结：每个阶段需要什么数据

1. **评测：开源 + 自建。** 先用开源的 QASPER、LongDocURL 测答案与证据；自建少量独立留出题，补拒答、工具故障和过程检查。
2. **SFT：自建轨迹为主。** 许可允许的开源训练集可做普通问答基线；工具调用示范用合成或授权文档、教师候选、真实工具返回和人工校验构造。
3. **Agentic RL：自建环境与轨迹。** 固定文档、工具和答案，从模型与环境交互产生轨迹；先做可验证的终局奖励。
4. **过程评估：自建标注。** 从实际轨迹标工具参数、证据和首个明确错误；标注质量可靠后，再决定是否训练过程奖励模型。

先小规模跑通和核验，之后再决定如何扩展到几万条。
