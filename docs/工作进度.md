## 发现的问题与证据边界

1. **16K 不适合当前标准 preset 的完整提示。** 实际 prompt 约 1.23 万 token，pi-ai 另留 4096 token，输出被裁为 1 token。实际服务和配置同时增至 32K 后通过。此结论针对本地配置，不能推广成 4B 必须使用 32K。
2. **GPU 编号和 CUDA 枚举不同。** 一次以数字选择的启动误选已满 A40，启动失败；已使用 UUID 修复，未停止他人服务。FlashInfer 编译遇旧 nvcc 后沿用原脚本禁用 sampler 的设置。排错时有用户级 FlashInfer 缓存写入（不在原件），随后补充隔离变量。
3. **摘要保持不等于动作遵循。** Web 压缩后模型从摘要中的旧待办继续找不存在的 appendix，违反新问题“不使用工具”的要求。最终答案数字／来源正确，但 JSON 前有额外文字；该演示不能算严格任务全通过。真实 PDF 问答也调用了不必要的 todo 工具。
4. **手动压缩必须等 agent idle。** 浏览器先看到回复文本就触发 `/compact`，第一次被正确拒绝；等 turn/end 后成功。自动化脚本须等待完成状态，不只等文本出现。
5. **全仓检查未全绿。** 最新 `test:docs` 为 15 通过／6 失败，`doc-sync` 为 34／9，剩余问题指向原有视频原型的 README、双语配对、相对链接、工具目录和包／tsconfig 注册。全仓 lint 也有该原型的格式／配置问题。没有修改无关原型来掩盖这些错误；本次改动的聚合类型、相关 lint 和压缩测试通过。
6. **数据与研究限制。** 官方 QASPER 页面／HF 数据卡本次访问失败，但 S3 数据包已下载；论文的 CC-BY-* 说明不能代替所有条款核验。论文全文已保存并核对方法，不宣称复现全部论文。种子未独立人工复标，未训练。
7. **管理器路径识别。** 完整新启动时发现相对命令 `python scripts/qwen_harness.py start` 不被绝对路径子串检查识别；已改为解析 NUL 分隔的 argv、相对进程 cwd 解析脚本，并核对 PID 启动时刻。相对／绝对路径、非管理命令、旧启动时刻均有检查，随后实际 stop／重启通过。
8. **实验限制。** 合成样本共享模板，四种文档类别只是标签；无压缩并未溢出，单次压缩加一次回答不能检验长期摊销收益；真实 PDF 问答不是 OCR，不验证 bbox 高亮或图表阅读。GPU 显存来自服务观测，未独立测峰值或能耗。
