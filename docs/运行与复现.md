## 环境与运行目录

已使用 Node `24.22.2`、pnpm `11.28.5`、vLLM `0.33.0` 和复制的 Qwen35-4B 权重。Node 来自 `/data/czj/.nvm/versions/node/v24.22.2/bin`；vLLM 来自 `/data/czj/anaconda3/envs/QDSH/bin`。它们是服务器已有环境，本次没有重装依赖。工作区 `runtime/smartdoc/workspace`、当前会话 `runtime/smartdoc/scientific-home`（旧 `dsh-home` 仅保留历史实验）、缓存 `runtime/smartdoc/cache`、临时文件 `runtime/smartdoc/tmp` 和实验结果 `runtime/smartdoc/results` 均在副本内。

`smartdoc_run.py` 验证隔离路径、选择 Node 24、进入副本源码目录并执行命令；禁止 pnpm 在运行命令前自动安装全部依赖。它移除当前不受 Harness 支持的 SOCKS 代理环境变量，仅影响子进程，不改变用户全局环境。

启动环境强制 `DSH_TELEMETRY_DISABLED=1`、`HF_HUB_OFFLINE=1` 和 `TRANSFORMERS_OFFLINE=1`。它们不等于操作系统网络隔离。科学配置只开放 read／glob／grep，关闭联网、编程、委派和外部默认模型；不要使用历史 baseline 配置启动日常问答。

## 服务参数

| 项目 | 当前配置 |
|---|---|
| 模型 API | `http://127.0.0.1:18001/v1`；模型 ID `qwen35-4B` |
| Harness Web | `http://127.0.0.1:13080/`，认证地址见启动日志 |
| provider | `smartdoc-local`，`openai-completions`，显式 `max_tokens` |
| 实际服务窗口 | 32768 token；与权重配置中的理论最大长度分开 |
| 推理 | thinking 关闭、eager、单 GPU、最多 1 个同时生成序列 |
| GPU | 本轮 A800 80GB；选择使用 GPU UUID，避免 CUDA 枚举顺序误选 A40 |
| 显存预算 | `gpu-memory-utilization=0.25`；不是端侧设备测试 |
| 自动压缩配置 | thresholdRatio 0.7、headroom 4096、摘要上限 3072、近期保留 2048 |
| 工具结果裁剪 | SmartDoc 配置禁用头尾裁剪，避免未评估的中间证据丢失 |

16K 配置的生产会话曾只输出 1 token：上游 pi-ai 在估算上下文后另留 4096 token，而既有系统提示及工具声明已约 1.23 万 token。改为真实 32K 服务与一致配置后完整回答通过。不要仅扩大客户端声明而不扩大服务容量。

## 启动和停止

推荐从副本根目录启动现有进程管理器；它保持前台，终端退出时清理自己启动的服务。

```bash
PATH=/data/czj/anaconda3/envs/QDSH/bin:$PATH python scripts/qwen_harness.py start
```

```bash
python scripts/qwen_harness.py status
python scripts/qwen_harness.py stop
```

管理器启动、状态、停止此前已验证；科学配置本轮再次用于本地真实 Web 测试。最终不保证服务持续在线，先执行 status，使用 stop 只管理自己持有的进程。

默认仅启动 4B。A3B 默认关闭，本轮没有验证其推理。若服务已由其他方式启动，管理器将其视为外部服务，不接管或停止。不能用复制而来的旧 `workspace/.run` PID 管理服务。

模型日志和 Web 认证地址在 `runtime/smartdoc/workspace/logs/`；本轮独立启动过程另保存在 `runtime/smartdoc/results/`。远程使用 Web 需转发 13080 端口，认证令牌不写入公开文档。匿名访问返回 401 是预期；须用日志中的完整认证地址，浏览器会保存登录 Cookie。HTTP 脚本需处理 Cookie 与重定向。

下面的源码命令已用于验证。`--patch` 必须放在应用选项 `--no-open` 之前，否则后续参数会被交给 Web 应用解析并报未知选项。

```bash
python scripts/smartdoc_run.py node --import tsx/esm apps/cli/src/bin.ts web --patch ../configs/smartdoc-model.patch.yml --patch ../configs/smartdoc-web.patch.yml --no-open
```

自动浏览器检查额外使用仓库已有的 `apps/web/tests/pin-browse-picker.overlay.yml`；这是测试目录选择器配置，不是新前端。

## 复现检查和实验

```bash
python scripts/check_isolation.py
python research/verify_config.py
python scripts/smartdoc_run.py node node_modules/vitest/vitest.mjs run packages/compaction/compaction-basic/tests packages/compaction/compaction/tests packages/compaction/compaction-tool-result-pruner/tests --maxWorkers=4
```

管理器完整新启动后的核验命令为 `python research/verify_supervisor.py`，要求默认模型／Web 都由管理器持有，检查真实回答、32K 容量和认证页面；外部服务模式不适用该检查。

真实模型实验需要模型服务已经启动。下列命令分别写开发／留出结果；重复运行会覆盖对应结果文件，保存已有实验时先复制结果目录。

```bash
SMARTDOC_REAL_MODEL=1 SMARTDOC_SPLIT=dev python scripts/smartdoc_run.py node node_modules/vitest/vitest.mjs run packages/compaction/compaction-basic/tests/smartdoc-model.spec.ts --maxWorkers=1
SMARTDOC_REAL_MODEL=1 SMARTDOC_SPLIT=heldout python scripts/smartdoc_run.py node node_modules/vitest/vitest.mjs run packages/compaction/compaction-basic/tests/smartdoc-model.spec.ts --maxWorkers=1
python research/summarize_results.py
```

上面两组冻结合成实验默认摘要预算仍为 1536，不读取部署预算。部署当前为 3072，二者须分开报告。

真实四篇 PDF、两道跨论文题的 3072 预算回归命令如下；这是开发诊断，不是独立留出测试。

```bash
SMARTDOC_REAL_MODEL=1 SMARTDOC_SPLIT=real SMARTDOC_CASES=research/real-cases.json SMARTDOC_SUMMARY_TOKENS=3072 SMARTDOC_RESULT_DIR=runtime/smartdoc/results/benchmark-long-3072 python scripts/smartdoc_run.py node node_modules/vitest/vitest.mjs run packages/compaction/compaction-basic/tests/smartdoc-model.spec.ts --maxWorkers=1
```

该命令会覆盖现有同名结果，复跑前另存目录或更改 `SMARTDOC_RESULT_DIR`。3072 原始记录、输入快照和哈希已保存。

合成结果目录为 `runtime/smartdoc/results/benchmark/`。输入在 `research/cases.json`，哈希在 `research/cases.sha256`；基线指令由上游代码提供，文档指令在 `configs/document-summary.txt`。同一指令也出现在两个部署 YAML 中，`verify_config.py` 校验一致性；改动时须同时更新。留出集不得参与调参。

当前 PDF 读取先由用户显式预处理：

```bash
python scripts/prepare_scientific_pdf.py runtime/smartdoc/workspace/你的论文.pdf
```

将返回目录的 `page-0001.txt` 路径发给原前端，让模型用 read 读取。首次选择工作区 `runtime/smartdoc/workspace`。同内容再次预处理拒绝覆盖，使用已有目录即可。扫描 PDF 没有文字层时失败，不自动联网或安装 OCR。

科学配置检查：

```bash
python research/check_scientific_pdf.py
python research/verify_scientific.py
```

后者核对已有组合配置导出及真实 Session；不是在模型未运行时生成新会话。浏览器复测启动时设置 `SMARTDOC_BROWSER_TEST=1`，随后运行 `node research/browser_scientific.mjs`。先归档旧输出，避免覆盖证据。源码组合配置通过 dsh 的 `--dump-config` 导出，不执行 YAML 中的 JS 表达式；运行时工具集合另外从 Session 请求头核对。

旧 `research/pdf-smoke-prompt.txt`／`results/pdf-smoke.jsonl` 使用 bash 读取 PDF，仅为历史记录。当前科学配置禁用 bash，不能照旧提示操作。历史完整 preset 的 16K 提示过大问题也不等于当前精简配置仍有相同提示长度。
