# SmartDoc 压缩实验报告

日期：2026-11-25。责任范围：陈子健的压缩优化、复杂任务评测与数据方案；沿用绪钊 Harness 和前端。原始结果保存在 `/data/czj/Qwen_DS_Harness_new/runtime/smartdoc/results/`，命令见[运行与复现](运行与复现.md)。

## 可以得到的结论

文档指令在这组小型合成测试中比默认编程摘要更能保留来源标识、页标签和单位要求；它没有超过无压缩基线的正确率，也没有在“一次摘要＋一次回答”中节省总时间。长输入真实论文任务暴露摘要预算不足，必须区分冻结的 1536 token 对照和之后的 3072 token 部署预算试验。

这不是完整 benchmark 论文结果：样本小、模板重复、单次运行，无显著性／置信区间；不支持“端侧可用”“无损压缩”“长任务全面优于单模型”等结论。

## 实际改动

上游 `BasicCompactionEngine` 已有自动压力、溢出恢复和手动压缩。本轮仅增加可选 `summaryInstruction`，不改变默认指令或 Session 格式。文档指令要求保留任务／更正、独立文档版本与证据、数值单位／否定、冲突和待办；默认工具结果头尾裁剪在实验配置中关闭。

部署使用原 `standard` preset 和前端，没有注册新文档工具。离线测试通过真实 Loader 核对 YAML 指令进入最终模型消息，并核对检查点进入真实 Session 投影；默认行为仍由原有测试约束。

## 冻结的合成对照

20 条固定规则生成的历史：4 开发、16 留出。包含论文／教材／财报／法律四种标签，但共享模板，并非真实领域数据。每题包含 v1→v2 更正、同值不同单位的另一个文档、物理页／印刷页、证据 ID、否定、未知 appendix 和待办；无实际历史工具执行。开发阶段发现“未获批≠被拒绝”标签歧义，先修正为 `not_granted` 并归档 v1，再运行留出集；未根据留出答案调参。

同一 Qwen35-4B，vLLM 0.33.0，A800 80GB，32K 窗口，thinking 关闭、温度 0、seed 42。实际调用 Harness 压缩引擎，经测试专用 HTTP adapter 请求真实 vLLM。冻结摘要上限 1536，最终回答上限 1024，近期一轮保留；实验 adapter 不经过生产 pi-ai 的估算裁剪，不将这里的耗时当作 Web 耗时。

输入为 `research/cases.json`（内容哈希随文件保存）；调用原文、摘要、最终答案、token 与耗时在 `results/benchmark/case-*.json`。原始代码快照和输入哈希在同目录。系统错误算失败，空答案不剔除；原本服务未就绪的失败开发运行另行归档。

### 哪些字段出问题

默认摘要的字段正确数：文档 ID／版本／数值／物理页／未知值均 16/16；单位 13/16、印刷页 15/16、证据 ID 9/16、否定 15/16、待办 15/16。

部分错误属于格式契约：`milliseconds` 写成 `ms` 语义等价，但用户要求保持原单位文本，严格匹配记为失败；“verify appendix content”与金标不完全相同也记为失败。因此 7/16 不是“只有七道题理解正确”。仍有实质错误：case-04 将证据块 b3 改成 b7；case-09 把印刷页写成物理页；case-17 以无关 archive notes 作为证据并丢失未获批信息。文档指令在本组避免了这些错误，不代表在任意文档都能避免。

## 真实论文补充实验

从本地 QASPER、FinQA、TAT-QA、LongDocURL 四篇 PDF 各取物理前四页，保留文档 ID、物理页和原文，构造两道跨论文题：数据规模／差值比较、TAT-QA 模型／人类 F1 及百分点差值。原始来源和 SHA-256 在 `research/real-source-ledger.json`，输入在 `real-cases.json`。没有调用原 benchmark 的测试题，也没有训练。原文通过已安装的 PyMuPDF 提取，不能据此评价图表视觉或 OCR。

完整输入分词约 20105／20097 token，低于实际 32768 窗口。首次保持摘要上限 1536 的对照结果：

| 方案 | 数量题严格字段 | 指标题严格字段 | 解释 |
|---|---:|---:|---|
| 无压缩 | 9/10 | 7/10 | 数字／计算正确；QASPER:p2 也支持金标事实，严格单一引用／名称匹配低估语义正确性 |
| 默认摘要 | 9/10 | 4/10 | 数量保留较好；指标题出现 improvement=0、问题数变成问题列表、待办 false 等实质问题 |
| 文档摘要 | 0/10 | 0/10 | 两次都触发摘要 token cap 截断，Harness 拒绝落地不完整 checkpoint；不能剔除 |

这里的真实题未预先穷尽所有可接受措辞／引用，因此严格字段分数只作为诊断。人工对照原文发现 QASPER 第 2 页也明确写有 5049／1585；这是评分局限，不是模型引用错误。后续正式评测须建立多个支持证据和规范化规则，不为提高某方案分数临时改动主表。

### 3072 token 预算试验

为解决长摘要截断，将两个部署配置的摘要上限提高到 3072、headroom 提高到 4096，并保留 1536 配置快照。对相同两道真实题重跑全部三组，摘要策略不变。这是根据已观察失败进行的开发调参，不是新的独立测试；结果单独保存在 `results/benchmark-long-3072/`，已完成全部 6 次任务执行，结果如下。

| 方案 | 数量题严格字段 | 指标题严格字段 | 后续输入均值 | 总输入均值 | 总输出均值 | 总耗时均值 |
|---|---:|---:|---:|---:|---:|---:|
| 无压缩 | 9/10 | 7/10 | 20389 | 20389 | 135 | 4.42 秒 |
| 默认摘要 | 9/10 | 4/10 | 1264.5 | 21904.5 | 1199 | 38.05 秒 |
| 文档摘要 | 7/10 | 7/10 | 2137.5 | 22759.5 | 2092.5 | 66.25 秒 |

文档摘要两次分别生成 1728／2121 token，均正常结束并落地检查点；修复的是本次两题的截断问题，不能保证任意长历史都不截断。数量题保留全部数字和差值，但把每篇 p1–p4 全列为引用数组，没有回答具体支持页，也不符合要求的字符串字段。指标题保留 58.0、90.8、32.8、11.1 与许可证待办，但问题数字段写成“5,049 questions over 1,585 NLP papers”。摘要正文还把 FINQA execution accuracy 混称 F1，并对已明确的 TAT-QA 任务提出不必要歧义；即使最终所需计算正确，也不能判摘要完全忠实。

评分将数值转字符串后比较，因此 JSON 数字 58.0 读入后变为 58，与金标字符串 58.0 不同；percentage-point／percentage-points 和预期措辞也不完全相同。主表保持原始评分，不事后更改金标；后续需分别评估数值语义、JSON 类型约束和证据支持。文档摘要本次后续输入减少约 89.5%，但总输入和总时间增加，不能声称总体提速。

本次预算回归的源码／配置快照和哈希在 `benchmark-long-3072/executed-sources/`、`run-input-hashes.json`，汇总在 `summary.json`。部署预算已采用 3072／4096；前面的 16 条合成留出表仍是 1536 的冻结实验，不冒充新预算独立验证。

## 原前端与实际工具闭环

`headless-smoke.jsonl` 证明完整 Harness 选用了本地 4B；`browser-smoke.png` 证明原 Web 前端可发送并收到 `SMARTDOC_WEB_OK`。源码版本显示 `0.2.2-rc.1-fcc0ad4-dirty`，dirty 包括接手前改动，不是发布版本标记。

`pdf-smoke.jsonl` 保存模型经已有 bash 使用 PyMuPDF 读取真实 QASPER 物理第一页的工具调用／返回，最终正确回答 5049 问题和 1585 论文并摘录原句。但模型还调用了 todo 工具，说明“只调用 bash”的约束没有完全遵循；这不算严格动作约束通过。

Web `/compact` 首次在回复文本出现但 turn 尚未结束时被拒绝；等 idle 后成功压缩 5 项历史，界面显示约 10150 token（Harness 启发式估算，不能当精确 tokenizer 差值）。后续回答保留数值、版本和来源，却又寻找旧待办 appendix，并在 JSON 前输出额外文字。原始 `web-compact-events.json` 记录 9 次额外工具调用，最终答案成功不掩盖这项失败。

## 验证与复现边界

相关离线测试 201 项通过；产物构建 8/8、聚合类型检查 2/2、修改范围 lint 通过。全仓 docs 和 lint 仍有既有视频原型问题，详见[工作进度](工作进度.md)。

本轮没有多次连续压缩实验、真正超长输入压力曲线、多人标注一致性、端侧硬件测量、真实 PDF 引用块高亮、教师蒸馏或训练。自动触发与工具配对／恢复主要由源码测试验证，不能等同于真实长期运行稳定性。

## 建议

短对话优先保留原始上下文；达到压力阈值再压缩。文档摘要作为可选配置，并保留回查原文的能力；长历史需要足够摘要预算，失败时保留原历史。下一阶段先解决最新指令与旧待办的优先级，再扩展真实文档和重复压缩；同时让团队接入真实证据块与坐标闭环。详细分工见[后续任务](后续任务.md)。
