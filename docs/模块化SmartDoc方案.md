# 科学文档问答模块设计

当前范围以[科学文档项目范围](科学文档项目范围.md)为准：个人电脑／手机本地科学文档问答；先用现有模型本地测试，后续蒸馏小模型。撤销原先“多行业文档类型 × 图谱／报告”等当前任务规划。

流程：本地 PDF／文本 → 按物理页提取文本 → 本地只读检索 → 小范围证据阅读 → 带出处回答 → 对话过长时生成文档检查点。

| 模块 | 当前实现／剩余工作 |
|---|---|
| 文档准备 | 固定预处理脚本调用已安装 PyMuPDF，页文本、来源文件哈希及页码保存在本机；不支持扫描 OCR |
| 阅读与检索 | 复用原 Harness read／glob／grep；没有模型 Shell 或编程工具 |
| 科学问答 | 现有本地 Qwen 4B；提示保留研究条件、数字、单位和不确定性 |
| 证据引用 | 当前来源名称、物理页与原句；证据块坐标及点击高亮仍待实现 |
| 对话压缩 | 复用现有 compaction 和文档摘要规则；继续修复引用过宽、指标混淆和旧待办抢占 |
| 端侧推理 | 当前服务器验证，未来评估 PC／手机运行后端与小模型；未实现手机应用 |

证据的最小字段为 document_id、source_sha256、physical_page、text；打印页码与物理页须分开。bbox 只有真实取得时才能加入。问答引用必须能回查原文，压缩摘要不是独立证据。

后续训练数据服务科学文档问答，不使用编程基准作为项目验收。模型规模和量化应由目标设备预算、阅读质量与延迟共同决定。
