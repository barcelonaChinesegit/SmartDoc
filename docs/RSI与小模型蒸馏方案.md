# RSI 与小模型蒸馏方案

更新：2026-11-25。责任人：陈子健。本文交付调研与可执行研究方案，不表示已实现自动自我改进或开始训练。当前实现和实验见[工作进度](工作进度.md)。

## 结论与本阶段选择

RSI 在这里指 Recursive Self-Improvement（递归自我改进）。修改上下文或保存经验是其中可研究的组成方式，但不能把任何一次摘要或提示修改都称为已实现 RSI。

先固定模型参数，把可改对象限定为摘要指令、任务策略和经过验证的经验条目；用开发集上的真实执行结果提出候选修改，再通过独立回归集决定接受或回滚。这是有限的系统适应，不足以证明开放式递归自我改进。会话压缩只负责当前任务的上下文预算，不自动形成可靠长期记忆。

本轮只实现可配置的摘要指令并做对照；不让智能体自动修改 Harness 源码，不安装新工具，不进行 SFT 或 RL。现有 Qwen 4B 是实际实验模型；“30B 教师蒸馏 3B 学生”是后续可检验路线，不能把当前 4B 实验写成 3B 成果。

用户确认后续自行蒸馏小模型，目标设备为个人电脑和手机。当前先用现有正常模型本地测试，不急于确定 3B／量化规格。以下含编程／游戏研究的论文仅保留为原始调研背景，借鉴反馈、版本和回滚方法，不转化为编程任务、可执行 skill 或代码进化工作。

## 三种更新须分别评估

| 层次 | 状态对象 | 允许的数据 | 验收 |
|---|---|---|---|
| 会话内压缩 | 当前任务检查点 | 当前已观察历史、来源、用户更正 | 原文定位可追溯，约束／证据保留，摘要与后续回答开销 |
| 跨任务适应 | 有版本的科学问答经验／提示配置 | 训练或开发任务的实际错误和成功执行记录 | 新任务质量，回归损失，额外调用次数，回滚成功 |
| 参数更新 | 学生模型或 LoRA 权重 | 许可明确、质量复核、与测试隔离的训练轨迹 | 独立测试集质量、遗忘、显存和延迟；当前未开始 |

## 建议的有限反馈闭环

1. 固定模型、文档划分和运行预算。保留原始文档及内容哈希，冻结测试清单。
2. 在开发集运行任务，记录实际请求、工具调用和返回、答案、引用、失败事件、模型 token 与耗时。没有执行的工具不得伪造“观察”。
3. 用可计算的答案／单位／页码规则和人工核验给出反馈。模型评分作为辅助列，不能作为唯一标签。
4. 教师提出一个候选摘要指令或一条经验增量，附适用范围、失败实例 ID、预期收益；不能复制测试答案进入记忆。
5. 同模型、同预算在开发集对比候选与当前版本；执行锁定回归集，记录成对差异。建议接受门槛：证据支持率不下降、关键约束不新增丢失、成本在团队约定上限内。门槛是研究建议，尚未经本轮统计校准。
6. 接受时保存旧版本、候选文本、差异、数据清单和结果；拒绝时保留原因。任何失败可恢复旧配置；正式测试仅在选定方案后运行。

经验条目建议字段：`id, version, scope, trigger, action, evidence_case_ids, observed_failures, validation_run, supersedes, expires_when`。当前摘要不可替代原始文档；发现引用缺失应重读原文或明确拒答。

## 30B 级教师到小模型：可行条件

教师不必是闭源 SOTA；关键是它在目标任务上经独立核验优于学生。先在小规模开发集比较教师和学生，统计教师也会犯的错误，避免“大模型即金标”。当前机器的共享 GPU 占用不支持无条件启动更大模型；需根据可用显存、上下文和量化配置单独测算。

可蒸馏对象包括正确答案、证据选择、可观察的工具动作、检查点和简短决策理由。服务未公开的内部思维链不能恢复；API 返回的解释也不能声称是真实内部推理。若自部署模型明确输出推理文本，仍须与实际工具轨迹区分并遵守模型许可。

后续建议先做不超过数百条的质量试验，按文档去重划分，保留不可回答、冲突版本和失败恢复案例。通过教师生成、规则筛选、独立复核后才考虑 LoRA。比较学生原模型、只用答案的 SFT、带证据／工具轨迹的 SFT；RL 作为更后阶段，首错检测信号需文档工具领域标注，不能把数学 ProcessBench 标签直接当成智能体奖励。

人工一致性至少采用两人独立标注、盲于策略、分歧仲裁，分别报告答案正确、证据支持、不可回答和动作合法性；报告样本数、原始一致率与适用的 Cohen κ，不用模型间一致率冒充人类一致率。本次没有执行人工标注，不能报告该指标。
