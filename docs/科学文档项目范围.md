# 科学文档问答：当前范围

用户最新确认：项目只处理科学文档，目标是在个人电脑和手机上本地读取可能含敏感内容的科学资料，并回答问题。当前先在现有服务器用正常模型验证，后续自行蒸馏小模型；现阶段不提前开展手机移植、量化或大规模训练。

## 当前需要保留的功能

本地科学文档读取；研究问题、方法、实验条件、结果和局限的问答；按文档和物理页引用原文；缺证据时说明未知；跨轮更正和长对话压缩；本地模型与原有 Web 前端；公开科学文档数据上的质量、引用和资源开销测试。

## 从当前产品移除的功能

编程角色、代码编辑／写文件／补丁工具、模型任意 Shell 或 Python 执行、编程计划模式、子智能体及代码工作流、定时任务、待办工具、可执行 skill 加载、联网搜索／抓取、插件安装入口和其他编程 preset。前端通过原框架插件配置去掉终端、内置浏览器、编程计划、子智能体、插件管理等入口，不另建前端。

当前不做金融财报、法律文件等通用多行业平台，不将知识图谱、长报告生成和视频处理列为项目待办。研究论文讨论财报数据集时仍是科学论文，例如 FinQA／TAT-QA 论文可以作为论文阅读材料，但不意味着提供财报业务。

上游框架源码、依赖以及历史实验原始记录保留供运行和追溯；实际 SmartDoc 配置不再加载编程能力。旧实验中的默认编程摘要仅为历史对照，不是当前产品提供的模式。

## 文档读取路径

当前既有 read 工具读取 UTF-8 文本，不能解析 PDF。先由用户运行固定本地预处理脚本，用已安装 PyMuPDF 提取 PDF 为按物理页分开的文本，并保留文件 SHA-256 和来源路径；模型只用现有 read／glob／grep 阅读和检索这些文本。没有新注册文档工具，没有开放任意命令执行。

这一步暂时在终端完成，前端尚未实现“上传 PDF 后自动提取”。原 PDF 预览可以用于核对；预览不等于模型已经阅读。扫描 PDF、复杂表格和公式需要进一步处理，不把纯文本提取算作 OCR 或完整结构化解析。

## 本地与敏感内容边界

默认模型地址为本机 127.0.0.1:18001，前端为本机 127.0.0.1:13080。关闭默认外部模型适配器、联网工具、反馈上传和遥测插件；启动环境设置模型缓存离线模式。科学配置使用独立 scientific-home，避免沿用旧编程会话及其设置。实际测试仅使用公开论文。

这些是配置收敛，尚不是完整的离线隔离或涉密环境验收。现有框架保存原文提取结果、附件、问答与会话日志；没有加密存储和可靠删除验收，也未完成全部进程出站流量测试。不要把“本地模型”直接等同于“已满足涉密部署条件”。后续需验证离线启动、数据保存位置、清理策略及文档内指令攻击等问题。

个人电脑和手机是最终目标，不是本轮已验证设备。当前 A800／vLLM 的显存占用和速度不能代表手机体验。未来先评估科学文档数据上的教师质量，再生成有真实证据的训练材料，蒸馏小模型，并分别在 PC 与手机评估内存、延迟、发热和准确率。

公网部署不是本地问答的依赖。继续不使用绪钊原域名或既有隧道；未来新 IP／域名若用于公开演示，仅使用公开样例并另行安排，不能将本地敏感文档自动发布出去。
