# SmartDoc 数据调研与构建方案

更新：2026 年 11 月 18 日。本版集中讨论 7 项与当前工作最相关的研究，已核对本地 PDF 的摘要和相关方法、数据、评估章节。下文区分原文做法和我们的方案；数量及时间是试运行建议，尚未通过实验验证。

## 项目问题

我们希望本地或受控环境中的文档智能体完成问答、抽取、总结和比较，并返回可核验的证据。当前先搭建不训练的原型，数据侧要分别评估答案、证据、工具执行过程和成本；后续才用验证过的数据研究 SFT 和智能体强化学习。

## 重点文献：做了什么，对我们有什么用

### 1. LongDocURL：按任务和证据类型拆分评测

[本地 PDF](../papers/pdfs/documents/2025_2025.acl-long.57_LongDocURL.pdf)｜[在线原文](https://aclanthology.org/2025.acl-long.57/)｜2025｜第 3 节、表 2、图 3。

**做了什么。** 构建长文档基准，将任务分为理解、数值推理和跨元素定位，按证据类型、单页或跨页等细分为 20 个子任务。最终 2,325 个问答样本覆盖 396 份文档、超过 33,000 页，约 52.9% 的问题涉及多页证据；证据包括正文、版面元素、表格和图形。

**数据怎么做。** 先筛选 PDF，解析出文本、类型和位置；通过多轮模型生成候选问答与证据；自动检查相关性、格式和忠实性，最后人工对照原始页面复核和修正。作者指出自动检查可能遗漏视觉结构，因而需要人工复核。

**我们借鉴什么。** 用“任务类型 × 证据类型 × 单页/跨页”组织评测。每题保存答案、文档 ID、支持页和证据类型；模型可以提议题目，但页码与内容要回到原文核验。先抽少量样例验证系统能否读取，再考虑扩大。

**边界。** 论文的定位包括由段落找到对应标题等跨元素关系，并不等同于逐字或坐标框定位；我们要另行设计页码、区域或单元格指标。表 2 仅有 2 条不可回答问题，不能单独衡量拒答。它是评测基准，不提供我们需要的工具调用训练轨迹；下载及许可需从[项目页面](https://github.com/dengc2023/LongDocURL)核对。

### 2. QASPER：答案和支持证据分开标注

[本地 PDF](../papers/pdfs/datasets/2021_2105.03011_QASPER.pdf)｜[在线原文](https://arxiv.org/abs/2105.03011)｜2021，作为基础数据集保留｜第 3–4 节。

**做了什么。** 针对 1,585 篇自然语言处理论文构建 5,049 个问题。提问者只看标题和摘要提出信息需求，另一组标注者阅读全文回答并选择支持证据。答案包括抽取式、生成式、是/否和不可回答。原文按论文切分训练、验证、测试，分别评估答案 F1 和证据 F1。

**我们借鉴什么。** 先用它验证“问题—答案—证据”链条。记录分别保存 `answer`、`answerable`、`evidence[]`，允许多个参考答案和证据；按文档切分，避免同一文档的问题跨训练和测试。合同或表格任务需另行验证泛化。

**边界。** 数据面向 NLP 学术论文，证据是段落、表格或图等，不能假定全部直接带 PDF 页码或坐标，也不包含完整工具交互轨迹。训练和再分发前核对[数据卡](https://huggingface.co/datasets/allenai/qasper)及源文档条款；测试集不参与训练。

### 3. DocAgent：先看结构，再按需读取和复核

[本地 PDF](../papers/pdfs/documents/2025_2025.emnlp-main.893_DocAgent.pdf)｜[在线原文](https://aclanthology.org/2025.emnlp-main.893/)｜2025｜第 3–5 节。

**做了什么。** 构建长多模态文档多智能体框架：先把章节、表格和图表等组织成树状大纲，为元素提供标识及页码信息；执行智能体通过交互接口按需获取内容；审查智能体用补充信息核查答案，经验存入记忆。论文在长文档基准上实验并分析组成模块。

**我们借鉴什么。** 设计文档目录和工具日志：目录保留章节、页码、元素 ID；记录“查看目录 → 搜索 → 读取证据 → 作答/复核”的实际执行。比较两篇报告时，分别定位对应章节并留证据，再比较结论。每步保留参数、实际返回和证据 ID，便于定位错误。

**边界。** 原文是系统方法，不是现成的文档 SFT/RL 轨迹集；多智能体和审查会增加调用与延迟，是否适合小模型需与单智能体、无审查方案对照。它没有证明我们的端侧资源约束已解决。

### 4. ToolACE：合成工具示范并分层检查

[本地 PDF](../papers/pdfs/agents/2024_2409.00920_ToolACE.pdf)｜[在线原文](https://arxiv.org/abs/2409.00920)｜2024｜第 2 节。

**做了什么。** 作者合成 26,507 个 API 的工具池，用用户、助手和工具角色生成对话，覆盖单次调用、并行调用、依赖调用和无需调用；使用目标模型评估并调整难度，再以规则和模型两层检查过滤。论文称部分数据和模型公开，具体版本及许可需核验。

**我们借鉴什么。** 固定 SmartDoc 的实际工具清单后，分别生成单次检索、跨页依赖、跨文档比较、无需工具和需要澄清的候选任务。先查工具名、必填参数、JSON 结构，再核查调用与用户需求、证据、答案是否一致；同时覆盖失败和重试，不只构造理想路径。

**边界。** 原文的工具角色可由模型模拟返回。为减少虚构页码和结果，我们拟用实际工具返回替换模拟观察，再检查证据并人工抽样；这是我们的改造，不是 ToolACE 已验证真实 PDF。通用函数调用数据不能直接替代文档轨迹。

### 5. Search-R1：根据检索反馈决定下一步

[本地 PDF](../papers/pdfs/agents/2025_2503.09516_Search-R1.pdf)｜[在线原文](https://arxiv.org/abs/2503.09516)｜2025｜第 3–4 节。

**做了什么。** 将检索器视为环境：模型输出查询，环境返回文本，模型据此继续推理、再次搜索或回答。训练时遮蔽检索返回 token，采用基于最终答案的结果奖励，并实验 PPO/GRPO 等方法。论文并未把过程奖励作为前提。

**我们借鉴什么。** 把文档解析、检索和页读取视为环境；记录模型动作及工具返回，让模型基于观察决定下一步。先用答案正确与证据支持等可核验终局指标建立奖励基线，再实验是否加入过程奖励。工具输出进入后续上下文，即使不作为助手生成目标。

**边界。** 检索语料和奖励不能直接照搬到 PDF/表格；工具结果遮蔽需由训练框架针对具体 token 和损失掩码实现、测试。答案正确不代表工具过程必然合理，仍需独立评测轨迹。

### 6. TRAJECT-Bench：评测工具执行过程

[本地 PDF](../papers/pdfs/agents/2025_2510.04550_TRAJECT-Bench.pdf)｜[在线原文](https://arxiv.org/abs/2510.04550)｜2025｜摘要及基准构造/评估章节。

**做了什么。** 用多领域工具和合成任务构建不同深度及并行度的调用轨迹，为同一轨迹生成直接和较隐含的两种请求。除最终答案外，还评估工具选择、参数约束、必需调用和依赖顺序，并在缺少标准轨迹时探索模型评判。

**我们借鉴什么。** 分别检查工具调用是否合法、参数是否指向正确文档或页、所需证据是否获取以及依赖顺序是否满足。同一文档任务可写直接和自然两种问法，观察对措辞的鲁棒性。允许多条合理路径，不把标准轨迹完全匹配当作唯一正确标准。

**边界。** 原基准是通用工具任务，不能直接代表文档页码、表格或解析质量；模型评判应与人工标注对照。我们尚未验证其数据是否适合直接复用。

### 7. ProcessBench：先标最早错误，再考虑过程奖励

[本地 PDF](../papers/pdfs/process/2024_2412.06559_ProcessBench.pdf)｜[在线原文](https://arxiv.org/abs/2412.06559)｜2024｜第 3–4 节。

**做了什么。** 构建 3,400 条数学解题过程测试样本，由专家标注最早错误步骤，评价模型找出该步骤或判断全程正确的能力。论文观察到一些已有过程奖励模型在更难数学题上泛化不足。

**我们借鉴什么。** 从 SmartDoc 实际运行的成功、失败轨迹抽样，标注首次可确认错误：例如检索错误文档、参数指向错误页、误读工具返回或证据不足就作答；不能判断时标为不确定。保留错误前状态和实际返回，检查标注者一致性。

**边界。** 它评测数学推理，不能直接作为文档智能体过程训练集；多条可行路径、工具故障和信息不足会增加首错判断难度。先验证标注可靠性，再决定是否训练过程奖励模型。

## 数据方案：来源、格式和用途

| 阶段 | 需要的数据 | 来源和构造 | 最小记录 | 当前动作 |
|---|---|---|---|---|
| 不训练原型评测 | 问题、参考答案和证据；包含可回答、不可回答、跨页题 | **开源** QASPER 测试集验证文本问答，LongDocURL 作为长文档候选；**自建**少量合成文档留出题 | 文档 ID、问题、答案/不可回答、证据文本和页码、评分规则 | 核对许可与下载方式，先抽 20–50 题跑通；LongDocURL 定位不等同坐标定位 |
| SFT | 工具调用、观察、最终回答和证据组成的示范 | **自建为主**：合成或授权文档、教师候选、实际工具执行、自动和人工校验；允许使用的 QASPER 训练划分可作普通问答基线 | 对话、工具 schema/参数、真实工具结果、证据 ID、答案、版本 | 先做 50–100 条试验样例并复核；开源 QA 不自动变成轨迹 |
| Agentic RL | 可重置任务、工具环境、参考答案及多条交互轨迹 | **自建为主**：与系统负责人固定工具、文档快照和奖励；模型与实际工具交互生成成功/失败轨迹 | 任务、快照、每步动作/观察、奖励、终止原因、模型和工具版本 | 先验证 20–50 条可重放任务及终局评分，再决定训练规模和算法 |
| 过程评估/奖励 | 标注过首错、工具参数和证据质量的轨迹 | **自建标注**：从实际运行结果抽样，双人试标并记录分歧 | 轨迹 ID、步骤、判断、错误类别或不确定、标注依据 | 先双人试标 30–50 条；先评估一致性，再决定是否扩展或训练 PRM |

规模是试运行目标，不是现成数据量或效果承诺。QASPER 和 LongDocURL 是第一轮候选；FinQA/TAT-QA 可在表格计算成为近期重点后补充。公开测试集与自建留出集只用于评测；按源文档和模板划分，避免训练泄漏。分别核对公开数据用于训练、再分发的许可及底层文档条款。

### 一条自建轨迹

用户问“两份合同的续约周期有什么不同”；系统分别检索 A、B 的续约条款，读取返回的页码和文本，再比较并带证据回答。每次记录工具名、参数和真实返回；如果 B 未检索到，示范应继续检索或说明证据不足，而不是编造页码。JSONL 结构见[数据样例](../data/examples/README.md)。

**CoT 和损失边界。** 可保存简短计划、可核验决策说明、工具动作、真实观察和证据；隐藏思维链不是必需标签。工具观察参与上下文，但一般不作为助手生成目标；训练掩码须由训练代码实现并测试，不能假定框架自动处理。

## 近期执行

1. 与系统负责人确定首批文档类型、工具清单、参数、返回结构及版本；登记公开数据许可、版本和切分。
2. 用 QASPER 和 LongDocURL 各抽小批题核对答案和证据，确认能否映射到现有工具；同时自建少量文档与留出题。
3. 用同一工具接口制作并执行 50–100 条 SFT 候选示范；检查工具返回、答案、证据与文档版本，记录失败原因。
4. 在系统支持重置后验证 20–50 条任务能否复现；抽取 30–50 条轨迹双人试标，作为奖励和过程评测设计依据。

实际进度依赖工具可用性、标注人力和许可核验；先检查小样本质量，再决定是否扩到会议讨论的几万条。

## 简要总结

- **评测：开源 + 自建。** 先用 QASPER、LongDocURL 测答案、证据和长文档；自建少量文档隔离的留出题补拒答和执行过程。
- **SFT：自建轨迹为主。** 许可允许的开源训练集可做普通问答基线；文档工具示范由真实工具返回、教师候选和人工校验构造。
- **Agentic RL：自建环境和轨迹。** 固定文档、工具和参考答案，从模型交互生成轨迹；先用可验证的终局奖励。
- **过程评估：自建轨迹标注。** 在实际结果中标首错、参数和证据；验证标注质量后再考虑过程奖励模型。
