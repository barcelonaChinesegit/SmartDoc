## 一、汇报开场（可直接讲）

这次我主要围绕绪钊的 Harness，完成了科学文档问答的本地流程验证、上下文压缩的免训练优化和对照实验，以及后续蒸馏所需的数据准备与调研。

当前目标明确为：让用户在个人电脑和手机上，本地阅读科学文档并回答问题，后续支持敏感资料的本地使用。现阶段先用已有 Qwen 4B 在服务器上验证功能，之后再自行蒸馏小模型。我们继续使用绪钊的框架和前端，当前产品只保留文档读取、检索、问答和压缩，停用了编程和联网相关能力。

目前真实论文的读取、回答、手动压缩和压缩后追问已经跑通。实验说明，针对文档设计摘要提示有助于保留部分证据，但暂时不能说总体更快或引用完全可靠。尤其是压缩后仍出现过来源文件名被编造的问题，这是接下来优先解决的内容。

## 三、现在用户怎样使用

当前实际流程如下：

```text
本地科学 PDF
  → 用户运行固定预处理脚本，按物理页提取文本并保存来源哈希
  → 在原前端选择工作区，指定文件并提问
  → 模型用现有只读工具查找和读取证据
  → 返回答案、来源页与支持原句
  → 历史较长时压缩，保留检查点并继续追问
```

`read` 读取文本，`glob` 查找文件，`grep` 检索文本内容。预处理脚本由用户显式运行，不是新增模型工具，也不开放任意命令执行。当前把 PDF 拖到前端不等于模型自动完成解析；PDF 预览也不等于模型已经读到了内容。

前端目前能展示对话、模型回答、工具读取记录及压缩完成提示。手动压缩需等待本轮回答结束，再单独输入 `/compact`。点击答案引用后定位并高亮 PDF 原文块，尚未实现。

公开样例 QASPER PDF 已提取 12 页。实际问答读取第 1 页，回答了 **5,049 个问题、1,585 篇论文**，并提供物理页码和支持句。模型仍可能添加无依据的解释，用户需要核对关键引用。

## 四、上下文压缩到底优化了什么

这里压缩的是模型继续对话需要的历史，不是面向用户生成一份论文摘要。例如先讨论论文 A 的样本数，再比较论文 B，随后更正 A 的版本；压缩应保留哪个数来自哪篇、哪个版本有效，以及支持证据在哪里。

本次添加的 `summaryInstruction` 是可选配置：填写后使用文档证据摘要；不填写时，上游框架保留原默认行为。当前科学部署已启用文档指令，用户不需要手动配置。默认摘要偏编程，只作为历史研究对照，不是当前提供给用户的编程模式。

验证分两层：

- **配置和消息结构检查**：真实 Loader 加载并组合配置，Session 快照检查压缩后模型能看到的消息。此类测试可使用固定模型响应，证明配置和消息结构符合预期，不能证明模型答案正确。
- **真实模型检查**：实际调用本地 Qwen 4B，并通过原 Web 操作，保存读取、摘要、回答和失败记录，用来评估内容质量。

当前服务上下文为 32K，部署摘要上限为 3072 token。自动压缩由上下文压力和预算共同决定，不是每隔固定轮数执行。生成摘要本身也消耗时间和 token，因此需要同时衡量信息保持、下一轮输入和总成本。

## 五、对照实验结果

### 1. 冻结合成实验：信息保持改善，总时间未下降

共 20 条合成历史，4 条开发、16 条留出；共享模板，早期的多行业名称只是标签，不代表当前产品提供多行业能力。三组均使用同一 Qwen 4B；冻结摘要预算为 1536 token。

| 方法 | 16 条留出题全字段匹配 | 后续回答输入 token 均值 | 摘要＋回答总耗时均值 |
|---|---:|---:|---:|
| 无压缩 | 16/16 | 2315.8 | 3.70 秒 |
| 原默认摘要 | 7/16 | 1602.4 | 20.52 秒 |
| 文档摘要 | 16/16 | 1741.1 | 24.80 秒 |

文档摘要让下一轮输入减少约 **24.8%**，本组字段保持好于默认摘要，但没有超过无压缩正确率；计入摘要后总时间增加。7/16 是严格字段匹配，部分失败来自等价措辞或单位写法，不能理解为仅有 7 题语义正确。没有重复后续问答的成本摊销测试，也没有统计显著性结论。

### 2. 真实论文诊断：预算不足会失败，增大预算后仍有质量问题

使用 QASPER、FinQA、TAT-QA、LongDocURL 四篇**科学论文**各前四页，构造两道跨论文问题，输入约 2 万 token。FinQA／TAT-QA 在这里是论文阅读材料，不是财报业务功能。

| 文档摘要预算 | 数量题严格字段 | 指标题严格字段 | 观察 |
|---|---:|---:|---|
| 1536 token | 0/10 | 0/10 | 两次摘要都被截断，框架拒绝落地不完整检查点；失败保留 |
| 3072 token | 7/10 | 7/10 | 两次摘要正常落地，但存在引用过宽、字段格式和指标名称混淆 |

3072 是针对同两题失败后的开发回归，不是新的独立测试。下一轮输入缩短不等于总耗时下降；正式评测还应分别衡量数值语义、格式约束和引用支持。

## 六、真实前端验证与暴露的问题

| 检查 | 实际结果 | 不能据此声称什么 |
|---|---|---|
| 科学模式文档问答 | 真实请求仅暴露只读的三个工具；QASPER 数字和物理页正确 | 不能保证整个回答都忠实；一次回答编造了缩写解释 |
| 手动压缩与追问 | 两个科学会话完成压缩和后续回答；追问没有调用工具，数字和页码保留 | 不能证明重复压缩或最新指令遵循已全面解决 |
| 来源保持 | 一次检查点把完整路径缩成省略形式，追问编造 `pdf_artificial_intelligence.pdf` | **流程运行完成，但严格来源忠实性失败** |
| 引用与提取 | 部分引用省略原词，单行标注不完整；双栏 PDF 的图例文字混排 | 不能称逐字引用、复杂表格或公式解析已验证 |
| 本地连接 | 浏览器观测请求仅到本机 Web；关闭默认外部模型、联网工具及遥测反馈 | 不能代替全部进程出站、读取权限和数据落盘检查 |

这些失败说明，下一步需要让文件名、页码和原文引用可核验，不能仅依赖模型“记住来源”。不通过删除失败记录或只展示正确数字来报告效果。

工程方面，已有 201 项相关离线测试、8/8 构建产物检查通过；科学配置收敛后另有 2/2 聚合类型检查及隔离／预处理检查通过。全仓文档和 lint 仍存在接手前视频原型的问题，未宣称全仓全绿。

## 七、数据、RSI 与后续蒸馏

QASPER 已下载的训练集为 **888 篇／2593 问**，开发集为 **281 篇／1005 问**，文档 ID 交集为 0。仅导出训练种子，保留参考答案、证据和不可回答标记；没有来源的页码／坐标不编造，没有执行过的工具轨迹保持为空。论文中的 1585 篇／5049 问是完整数据集规模，与已下载 train/dev 的数量区别说明。

RSI 调研的重点是区分三件事：会话压缩改变当前历史；经验或提示更新改变未来任务策略；蒸馏改变模型参数。当前只做了第一类的配置优化与实验，后两类仍是研究方案。7 篇相关论文借鉴反馈、验证与回滚方法，不开展代码自我进化或编程任务。

下一步先用公开科学资料核验教师是否确实优于学生，再生成少量带证据的答案、摘要和实际阅读轨迹，经过复核后讨论小模型蒸馏。目标是科学文档能力和端侧资源开销，不预先承诺模型大小或手机速度。

## 八、下一阶段优先顺序

1. **先修复来源与引用质量。** 针对编造文件名、缩写解释、引用缺词建立回归样例，分别检查答案正确和证据支持；缺证据时允许明确拒答。
2. **再验证真实长程任务。** 多篇论文、多次压缩、版本更正和取消旧任务；记录失败、总 token、总耗时，开发集调参、独立测试验收。
3. **补齐本地使用边界。** 验证断网运行、所有进程出站、文档可读范围，以及原文、附件和日志的保存／清理；完成前仅用公开材料测试。
4. **与绪钊、浩天对齐文档使用流程。** 沿用原前端，明确自动预处理和引用定位的接口及分工；当前不擅自接新工具。
5. **推进教师小试和后续蒸馏。** 完成许可与种子复核，验证教师质量后再制定训练方案，最后分别在 PC 和手机上测内存、延迟与准确率。

当前尚未实现或验证：PC／手机部署、小模型蒸馏、涉密环境验收、上传 PDF 自动解析、OCR、引用块高亮及长程稳定性。多行业、图谱、长报告和编程业务不列入本阶段任务。

## 九、现场展示顺序（约 3–5 分钟）

1. 说明当前科学文档目标及分工，展示原 Web 与 `SmartDoc Qwen 4B`。
2. 展示已准备的 QASPER 按页文本，提问问题数／论文数，并核对物理第 1 页；明确预处理在本机终端完成。
3. 等回复结束，输入 `/compact`，完成后要求重复数字、文档名和页码。检查来源是否正确；失败时展示并解释，不预先保证正确。
4. 展示上面的三组对照表，说明“下一轮输入降低、总成本增加”，再展示真实论文和文件名幻觉案例。
5. 说明数据种子与下一阶段优先事项。
