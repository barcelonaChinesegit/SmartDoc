# Demo 系统调研与展示方案

更新：2026-11-25。责任人：陈子健，与绪钊对接。此项是系统展示标准调研，不包含投稿、KDD、专利或对外发布。

## 官方标准说明什么

核对了 [ACL 2025 System Demonstrations](https://2025.aclweb.org/calls/system_demonstration/) 和 [EMNLP 2025 Demos](https://2025.emnlp.org/calls/demos/) 官方征稿页面，作为历史标准参考，不推断下一届时间与格式。

两者要求说明问题、目标用户、技术设计、新意、已有系统比较、许可及评价；没有任何评价可能被直接拒稿。均要求不超过 6 页正文，以及最长 2.5 分钟演示视频，并提供可访问演示或可下载安装包（特殊硬件例外需说明）。ACL 2025 附录最多 2 页；EMNLP 2025 页面允许额外 informative appendices，二者不能混写。均为单盲评审。未来选择具体会议时须重新核对当届要求。

因此“Demo 比主会要求低”不能当成无需技术贡献或实验的理由。SmartDoc 要展示稳定、完整的实际使用流程，并有同模型基线、质量和成本证据。

## 三个原始系统实例

PDF 和逐页文本保存在副本 `research/sources/`，下载来源和哈希在 `papers-manifest.json`。以下观察来自论文，不表示已安装复现这些系统。

| 系统／论文 | 可核验的系统内容 | 对 SmartDoc 展示的借鉴 |
|---|---|---|
| [SlimLM: An Efficient Small Language Model for On-Device Document Assistance](https://aclanthology.org/2025.acl-demo.42/) | 摘要、问答、问题建议；Samsung Galaxy S24 实机，模型大小／上下文／推理时间比较，提供 Android 应用与模型 | “小快”必须有目标设备实测；本项目 A800 的结果不能写成端侧部署。需要清晰用户任务和可安装交付 |
| [Unifying Language Agent Algorithms with Graph-based Orchestration Engine for Reproducible Agent Research（AGORA）](https://aclanthology.org/2025.acl-demo.11/) | 图式模块编排、复用算法、跨模型／任务评价，代码、演示与比较页面 | 模块化的价值需用可重放配置和公平对照证明，模块数量多不等于更强 |
| [FlexRAG](https://aclanthology.org/2025.acl-demo.60/) | 面向研究与原型的 RAG 框架，文本／多模态／网络检索，异步和持久缓存，实验对照 | 分离模块成本与总体任务成本，明确已有框架与项目新增能力的边界 |

特别注意：ACL 2025 Demo 中另有同名 DocAgent，主题为代码文档生成；它与本组讨论的长文档问答 DocAgent 不是同一篇论文。

## 建议的 150 秒演示脚本

| 时间 | 画面／操作 | 需要的证据 |
|---|---|---|
| 0–20 秒 | 说明目标用户、选择文档与任务 | 文件真实存在、类型与版本标明 |
| 20–50 秒 | 提问并查看带来源的答案 | 回答、来源页和原文；当前没有闭环的高亮不能用剪辑伪装 |
| 50–90 秒 | 加入版本更正、冲突或第二份文档，触发压缩后继续 | 展示真实 checkpoint、最新约束与来源保留，故障时明确失败 |
| 90–120 秒 | 展示相同任务三组结果 | 同模型、同输入、摘要成本计入总耗时；说明合成或真实样本 |
| 120–150 秒 | 说明如何启动、当前限制与下一步 | 可执行命令、环境条件、未实现模块清单 |

这是一份录制脚本，不是已录制的视频。当前可演示范围由进度证据决定；真实 PDF 引用高亮尚未完成；图谱／报告与多行业流程已移出当前范围。展示只使用公开科学材料，不能把当前服务器测试写成 PC／手机端侧验证。

## 系统稿件所需材料（暂不投稿）

准备架构图、用户操作链、复现说明、真实失败案例、基线对比、消融与成本表。对比重点是“现有 Harness 如何在同模型条件下保持文档证据和任务状态”，不能把绪钊已有框架和前端算作子健的新贡献。若评测仅显示 token 下降但总时间增加，也应如实展示；没有显著效果时优先修复系统与评测，不先包装论文结论。
