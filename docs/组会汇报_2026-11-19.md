# SmartDoc 数据与训练安排讨论稿

> 历史资料：当前范围已收敛为科学文档本地问答，详见 /data/czj/DocAgent/docs/科学文档项目范围.md。非科学文档、编程与未实现的工具／平台设想不作为现行任务。原文保留供追溯，不能据此启动旧配置或声称已实现。

日期：2026 年 11 月 19 日

## 数据怎么分

公开问答数据可以教模型读文档、找证据和做表格推理，但它们没有 SmartDoc 实际工具执行返回，不能直接当成完整的 agent 轨迹。训练集只进训练；同一数据集的验证/测试划分留到训练后评测，不能混用。

| 数据集 / 来源 | 用途 | 阶段 | 是否直接可用及限制 |
|---|---|---|---|
| **QASPER** | 论文全文问答、答案与证据定位 | LoRA-SFT 的普通问答阶段；测试划分用于训练后 benchmark | 训练划分可转成“文档 + 问题 → 答案 + 证据”的监督样本。它不是合同或表格数据，也不含工具调用轨迹；检查数据和源论文许可。 |
| **FinQA** | 财报表格/文本上的数值推理，含答案及可执行推理程序 | LoRA-SFT 的数值推理阶段；保留测试划分作 benchmark | 使用训练划分训练取数、运算和答案表达；推理程序可作为结构化监督目标或校验依据。它不是文档检索工具轨迹。 |
| **TAT-QA** | 财报表格与关联段落的混合问答，含证据、答案类型及数值推导 | LoRA-SFT 的表格与跨文本推理阶段；保留测试划分作 benchmark | 使用训练划分训练表格单元格/段落取证、计数和计算。论文公开页面注明非商业使用；核实许可后再用于训练。 |
| **SmartDoc 自建文档问答集** | 我们目标文档上的答案、证据页/区域、可回答性 | 原型评测集；SFT 数据筛选与验证 | 选合成或获授权 PDF/Word/Excel，由人核对答案和证据。按文档划分训练与留出集。 |
| **SmartDoc 实际工具轨迹** | 解析、检索、读页/表、计算、复核等真实动作与观察 | LoRA-SFT 的 agent 轨迹阶段；后续 Agentic RL 的任务池与环境 | 必须由 SmartDoc 工具实际执行生成观察，保存动作、参数、原始返回、证据 ID、终止原因；不能让生成模型伪造工具返回。 |
| **LongDocURL** | 长文档理解、数值推理、跨元素定位 | 训练后的外部 benchmark 候选 | 不进训练。先核查数据及源文档许可；用于检查长文档、多页和多模态证据表现。 |
| **DocBench、MMLongBench-Doc** | 长文档问答与多模态文档能力 | 训练后的外部 benchmark 候选 | DocAgent 论文用它们评测系统；SmartDoc 仅在获取数据并确认许可后使用，不拿论文演示轨迹训练。 |
| **TRAJECT-Bench** | 通用工具选择、参数和轨迹评测 | 训练后的工具使用外部 benchmark 候选 | 不作为文档训练数据；许可允许时测通用工具使用能力，不能替代文档证据评测。 |
| **ProcessBench** | 数学推理过程首错识别 | 仅参考标注任务；SmartDoc 过程评测集需自建 | 不把数学样本用于 SmartDoc 训练。按其首个错误步骤和多标注者复核方式标注文档工具轨迹。 |

公开数据的训练划分与 benchmark 划分必须严格隔离。同一个公开数据集可以用 train split 做 SFT、test split 做 benchmark，但要按源文档去重；公开问答样本转成答案监督时，不得自行补造工具调用和工具观察。

## 训练阶段与 LoRA / SFT / 强化学习

这里的 **SFT 是训练目标/阶段**，**LoRA 是参数高效微调方法**，二者不是互斥选项。当前建议先用 LoRA 做 SFT；Agentic RL 是之后独立的训练阶段。

| 顺序 | 阶段 | 使用的数据 | 训练内容与边界 |
|---|---|---|---|
| 0 | 不训练基线 | QASPER、FinQA、TAT-QA、LongDocURL 等各自的评测划分；许可允许的 DocBench / MMLongBench-Doc | 先测基础模型，不看训练数据上的结果。分别记录答案、证据、数值推理、页码/区域定位和工具成功率。 |
| 1 | 普通问答与证据 LoRA-SFT | QASPER train；SmartDoc 自建的答案、证据和拒答样本 | 让模型根据给定文档回答并提供证据。QASPER 学术论文域与目标文档存在差异，作为起步数据，不视作目标域最终数据。 |
| 2 | 表格/数值 LoRA-SFT | FinQA train、TAT-QA train；目标文档中的授权表格样本 | 学习从表格和段落取数、选择运算、保留单位/量级并回答。FinQA 的推理程序、TAT-QA 的证据与 derivation 可作监督；数据格式需统一。 |
| 3 | 工具调用 LoRA-SFT | SmartDoc 自建并真实执行、人工抽查的 agent 轨迹 | 学习何时调用何工具、参数怎么填、如何根据真实观察继续或停止、如何引用证据。上述公开 QA 数据不含这类完整交互，不能替代本阶段。 |
| 4 | Agentic RL | SmartDoc 可重置的本地工具环境；由自建任务池或公开训练划分改造成的任务种子；在线采样的模型—工具轨迹 | 每个 episode 固定文档快照、工具版本和可验证目标。奖励先看答案正确、证据是否支持、调用是否合法及是否正确停止。静态 QA 记录只是任务种子，不是现成 RL 轨迹；训练中产生的动作和观察才构成 rollout。 |
| 5 | 训练后 benchmark | QASPER / FinQA / TAT-QA 的留出测试集；LongDocURL；许可允许的 DocBench、MMLongBench-Doc；SmartDoc 自建留出集 | 公开测试集不回流训练。SmartDoc 自建集按文档、来源和模板隔离，专测真实工具轨迹、拒答、失败恢复及页/区域证据。 |

RL 阶段不应把工具返回文本当成模型要生成的目标。训练实现需要对环境提供的观察 token 做损失掩码并验证；这是 Search-R1 值得借鉴的处理。先做终局可验证奖励，再决定是否增加过程奖励，避免一开始用未经验证的过程分数主导训练。

## 要借鉴的论文流程

| 论文 | 我们要借鉴的流程 | 落到 SmartDoc 的做法 |
|---|---|---|
| **QASPER** | 提问、答案和支持证据分别标注；不可回答单独标记；按文档切分 | QA 样本同时保存答案、可回答性和证据，不只存一段目标文本。 |
| **FinQA** | 从表格/文本找数，再生成可执行的数值推理程序 | 对计算类问题保留数值来源、运算式、单位和答案；程序可执行校验。 |
| **TAT-QA** | 表格与关联段落联合取证，区分抽取、计数和算术问题，保存 derivation | 让文档题覆盖表格单元格与正文互补证据；校验数字量级和单位。 |
| **LongDocURL** | 按任务类型、证据类型、单页/跨页划分评测 | 自建 benchmark 分开测正文、表格、图像、跨页和跨元素任务。 |
| **DocAgent** | 先生成带章节/页码/元素 ID 的 outline；Actor 按需读取；Reviewer 用补充证据复核 | 先建目录工具和按需读取日志；Actor/Reviewer 作为对照实验，验证收益后再保留。 |
| **ToolACE** | 工具池与 schema 固定；覆盖单次、并行、依赖、不调用；规则检查后再做语义检查 | 按真实工具 schema 合成候选任务，检查参数类型、必填字段、调用与需求/答案的一致性。ToolACE 可模拟结果，SmartDoc 必须用真实工具返回替换。 |
| **Search-R1** | 模型与检索环境多轮交互；根据观察继续搜或作答；结果奖励；环境返回不计入生成损失 | 把搜索环境换成本地文档工具；先用可核验终局奖励，环境观察进入上下文但遮蔽其生成损失。 |
| **TRAJECT-Bench** | 分别评测工具选择、参数、轨迹覆盖/充分性和依赖关系；直接问法与隐含问法都测 | 每条自建任务保存必要证据与依赖约束，允许多条正确路径，不能只比对唯一工具序列。 |
| **ProcessBench** | 标注完整过程中的最早明确错误；困难样本多人复核；不确定样本不硬判 | 从真实文档轨迹标首错位置，如错文档、错参数、误读观察、证据不足作答；先双人试标并统计一致性。 |

这里说的“借鉴/照着搭”是复用任务设计和质检流程，不是照搬论文数据、工具或模型。特别是 ToolACE 的模拟工具反馈不能作为 SmartDoc 训练中的事实观察；Search-R1、TRAJECT-Bench 的网页/通用工具环境也不能替代本地文档环境。

## 需要讨论确认的执行顺序

1. 先跑不训练基线，核对 QASPER、FinQA、TAT-QA 的许可、格式和文档可获取性；LongDocURL 与 DocBench 系列核对 benchmark 使用条件。
2. 统一普通 QA 与表格 QA 格式，分别整理 train/dev/test，按源文档去重，先试小批 LoRA-SFT。
3. SmartDoc 工具稳定后，执行并复核第一批 agent 轨迹，再做工具调用 LoRA-SFT；SFT 成功率和证据质量达标后再进入 RL。
4. 固定可重放的工具环境、文档快照和奖励，才开始 Agentic RL；训练完成后只在隔离的测试集和自建 benchmark 上报告结果。

## 最终结论

- **普通问答/证据 SFT：** QASPER train；SmartDoc 目标文档问答与拒答数据自建。使用 LoRA 实现 SFT。
- **表格/数值 SFT：** FinQA train + TAT-QA train；补充授权的 SmartDoc 表格样本。使用 LoRA 实现 SFT。
- **工具调用 SFT：** SmartDoc 工具实际执行后自建轨迹；公开 QA 数据不能替代。仍先用 LoRA-SFT。
- **Agentic RL：** 自建可重置环境和在线 rollout；公开训练集最多提供任务种子。先做终局奖励，不直接复用论文静态数据作 RL 轨迹。
- **训练后 benchmark：** QASPER、FinQA、TAT-QA 留出测试集；LongDocURL 和许可允许的 DocBench / MMLongBench-Doc；再加按文档隔离的 SmartDoc 自建集。TRAJECT-Bench 只作通用工具诊断候选。
- **流程借鉴：** QASPER 的证据标注、FinQA/TAT-QA 的数值推导、LongDocURL 的任务分层、DocAgent 的 outline/按需读取/复核、ToolACE 的数据生成与双层校验、Search-R1 的交互 RL 与观察损失掩码、TRAJECT-Bench 的轨迹评测、ProcessBench 的首错标注。
