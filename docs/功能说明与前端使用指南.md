# 科学文档功能说明与前端使用指南

更新：2026-11-25。项目只面向科学文档阅读和问答。最终目标是个人电脑和手机；当前仍在本地服务器上用 Qwen 4B 验证，后续才蒸馏小模型。前端沿用绪钊的 Harness。

## 1. 作为用户，现在能做什么

| 操作 | 当前效果 | 如何使用 |
|---|---|---|
| 阅读科学论文并提问 | 根据已提取的论文文本回答研究问题、方法、数据和结果，要求给出处 | 先按下文准备 PDF，再在对话框给文件路径和问题 |
| 在本地文本中找证据 | 模型通过原有 glob 找文件、grep 找关键词、read 读取相关行 | 可以说“在这些页中找实验样本量，给出原句和物理页码” |
| 连续追问或更正 | 在同一会话补充问题和限制 | 例如“刚才只比较数据规模，现在比较标注方式；没有原文不要猜” |
| 手动压缩历史 | 模型把较早对话写成检查点，后续回答使用检查点和近期消息 | 等回复完成后单独输入 `/compact`，等待完成，再提问 |
| 自动压缩 | 上下文压力达到配置条件时，Harness 自动尝试压缩 | 不用每隔几轮手动操作；不是每 N 轮固定触发 |
| 核对文件／PDF | 使用原前端已有文件预览 | 预览只帮助人核对；PDF 能显示不代表模型已经解析 |

当前没有实现点击答案引用后高亮 PDF 对应块，也没有一键上传 PDF 自动解析、扫描件 OCR、图表视觉理解。源文件正文能提取出来不等于复杂表格和公式已正确还原。

## 2. 本地使用步骤

全部操作在 `/data/czj/Qwen_DS_Harness_new`，不要在原件目录运行。完整环境说明见[运行与复现](运行与复现.md)。

1. 将要阅读的文本型科学 PDF 放到副本 `runtime/smartdoc/workspace/` 中。当前公开样例为 `qasper-paper.pdf`。
2. 在终端运行一次固定预处理脚本：

```bash
python scripts/prepare_scientific_pdf.py runtime/smartdoc/workspace/你的论文.pdf
```

脚本只用现有 PyMuPDF 提取文字，返回输出目录。目录内 `page-0001.txt` 表示物理第 1 页，`manifest.json` 记录来源路径、内容哈希、页数和空页。它不由模型调用，不是新增智能体工具。加密／无可提取文字 PDF 会明确失败。相同内容已提取过则拒绝覆盖，直接使用原输出目录即可。

3. 启动本地模型与原前端：

```bash
PATH=/data/czj/anaconda3/envs/QDSH/bin:$PATH python scripts/qwen_harness.py start
```

打开启动日志中 `127.0.0.1:13080` 的完整认证地址。日志中的令牌不要分享。若浏览器在另一台电脑上，使用自己的 SSH 转发到这个本机端口；这不使用旧公网域名。首次进入选择副本的 `runtime/smartdoc/workspace` 工作区。模型应为 `SmartDoc Qwen 4B`。

4. 将预处理返回的目录粘到问题里。例如：

> 请读取 `<输出目录>/page-0001.txt`，回答这篇论文的数据集有多少个问题、多少篇论文。只给文档名、物理页码、数字和支持原句；不要扩展解释没有证据的术语。

5. 回复完成后输入 `/compact`。看到压缩完成再追问：

> 只根据刚才保留的证据重复两个数字及出处，不调用工具；证据不足就说明不足。

用完后执行 `python scripts/qwen_harness.py stop`。不要根据历史 PID 手动杀进程。

当前文本型 QASPER PDF 已成功提取 12 页；真实 Web 会话确实调用 read，回答 5049／1585 和物理第 1 页原句。模型曾额外编造 QASPER 缩写解释，另一次压缩后编造了文件名 `pdf_artificial_intelligence.pdf`。因此不能把数字答对写成整段回答完全可靠。

## 3. “可选文档摘要指令，默认行为保留”是什么意思

这里的“摘要”主要是给模型继续工作用的**对话记忆**，不是给用户生成论文摘要的按钮。

假设先讨论论文 A 的样本数，随后读论文 B，再更正 A 的版本。如果每轮都发送全部原文和历史，输入会越来越大。Harness 可以把旧历史替换为一份短检查点，并保留近期消息。文档摘要指令要求检查点保存任务、文档版本、页码、原句、数字／单位、冲突和未解问题，避免只剩模糊结论。

新增可选配置字段名是 `summaryInstruction`。未配置时仍使用上游的默认摘要提示，原框架的默认行为保留；配置时使用科学文档更需要的证据提示。当前 SmartDoc 部署已启用文档提示，用户不需要在聊天里设置。旧默认提示偏编程，仅用于历史实验对照，不是当前产品的一种编程模式。

没有重新造一套 Compact 框架，没有训练压缩模型。摘要仍由当前本地模型生成，会花时间和 token，也可能丢信息。它能减少下一轮输入，不保证总体更快，更不保证无损。

当前服务窗口 32768 token，摘要上限 3072，近期保留预算 2048，压力比例 0.7、额外余量 4096。自动触发还要考虑输出预算和可压缩区间，不能简单理解成“超过 70% 就一定压缩”。

## 4. 自动压力、溢出恢复和工具配对

**自动压力触发**：发送下一次模型请求前，框架估算上下文是否过满；需要时先压缩旧历史。

**手动 `/compact`**：用户主动让同一机制执行一次。必须等模型停止工作。历史过短或没有可压缩内容时，不保证一定生成检查点。

**溢出恢复**：若模型服务实际拒绝过长上下文，框架尝试利用压缩恢复。它不是无限窗口；不能恢复时应保留失败。当前相关行为主要由框架测试覆盖，不能说所有真实长文档都验证成功。

**工具配对**：一次 read 调用要和它返回的原文对应。压缩切分不能留下没有调用来源的工具结果，或没有结果的调用片段。这保障消息结构可被模型理解，不保障模型引用一定正确。

## 5. “真实 Loader 与 Session 快照验证”是什么意思

**Loader** 是 Harness 的配置加载器。部署有基础配置、模型配置、Web 配置和会话 preset；只看某个 YAML 并不能知道最终谁覆盖了谁。测试用框架真实的加载器组合配置，检查文档摘要指令是否传到了实际压缩模块。

**Session** 是一次会话的记录，包含用户消息、模型回答、工具调用及返回、压缩检查点和模型请求信息。

**快照** 是保存某一步模型应该看到的完整消息结构，再逐项比较。比如压缩后应该有文档检查点和最近一轮提问，不应该重新塞回整段旧工具输出。

这组测试使用真实框架组件，但模型响应可固定，以便稳定检查配置和消息结构；不是拿真实 Qwen 验证每条内容。另有真实模型实验和浏览器会话。当前科学配置还检查了真实 Session 请求头：模型只拿到 read、glob、grep，provider 为本地模型。这两类证据不能混称。

这些检查供开发者维护，普通用户在前端不会看到“Loader 验证”按钮。

## 6. 复杂任务对照有什么用

用同一 4B 比较三种方法：发送完整历史、上游默认摘要、文档证据摘要。这样主要比较压缩策略，而不是换模型带来的差异。

历史冻结实验包含 20 条合成历史（4 开发、16 留出），其中多行业名称是早期模板标签，不是当前产品功能。1536 摘要预算下留出全字段匹配分别为 16/16、7/16、16/16；文档摘要让下一轮输入减少约 24.8%，但总时间增加。

另有 4 篇真实论文的两道跨文档题，仅使用各篇前 4 页。1536 文档摘要均截断；3072 开发回归不截断，但两题严格字段均为 7/10。引用过宽、指标混淆等失败保留。这些是开发评测，不是前端按钮，也不能当科学领域全面通过或手机性能证明。详见[实验报告](压缩实验报告_2026-11-25.md)。

## 7. RSI、蒸馏、数据和 Demo 是什么

| 项目 | 含义与作用 | 当前前端是否已有 |
|---|---|---|
| 会话压缩 | 在同一任务中缩短历史，让模型继续回答 | 有，自动机制和 `/compact` |
| RSI 调研 | 研究如何从实际错误提出提示／经验改进，再测试并回滚 | 没有自动自我改进按钮；已完成研究方案 |
| 小模型蒸馏 | 后续让较小学生模型学习质量已核验的教师答案、证据选择和操作记录 | 没有；当前 Qwen 4B 未做本项目训练 |
| QASPER 种子 | 科学论文与人工问答，作为后续教师生成和评测的起点 | 没有训练页面；已下载原 train/dev，仅导出 train 种子 |
| 模块化 | 把本地文档准备、按需阅读、答案引用、历史压缩、评测分清职责 | 部分运行组件已有；未实现可视化流程搭建器 |
| Demo | 展示实际产品链路和证据的系统演示 | 有原前端；有150秒脚本，尚未录制视频 |

QASPER 训练集为 888 篇／2593 问，开发集 281 篇／1005 问；论文中 1585 篇／5049 问描述完整数据集，包含这里未导出的其他划分，两者没有矛盾。

## 8. 公网和本地边界

原件源码默认端口与副本不同，但没有查明绪钊的真实公网域名和远端代理，因此不能判断是否同一网址。当前不使用旧网址或隧道，不发布服务；以后收到新 IP／域名再安排公开样例展示。

科学配置关闭联网搜索、外部默认模型、遥测与反馈插件，使用独立 scientific-home 保存会话。浏览器实测请求仅到本机 Web，这不等于完成所有服务器进程的出站审计。原文、提取文本和对话日志仍会落盘，读取工具也未验证为仅能访问指定文档目录。当前测试只用公开论文；涉密本地部署还需要验证断网运行、访问范围和数据生命周期。不能把服务器上跑通当作 PC／手机已部署。
